# รายงานตรวจความครอบคลุมระบบเทียบเอกสารโครงงาน

วันที่ตรวจ: 16 กันยายน 2569 (2026-09-16)

> **อัปเดตหลังลงมือแก้ระบบ:** ผู้ใช้ยืนยันให้ใช้ OpenAI API และให้เลื่อน benchmark แบบ blind 10 × 30 ไว้ก่อน งานแก้และผลตรวจล่าสุดอยู่ใน [IMPLEMENTATION_PROGRESS.md](./IMPLEMENTATION_PROGRESS.md) ซึ่งใช้เป็นสถานะปัจจุบัน ส่วนข้อ 1–8 ด้านล่างเก็บไว้เป็นผลตรวจ **ก่อนแก้** เพื่อย้อนดูเหตุผลและข้อกำหนดเดิม ไม่ใช่รายการปัญหาที่ยังคงอยู่ทั้งหมด

## 1. ข้อสรุป

**ระบบปัจจุบันยังครอบคลุมเอกสารไม่ครบ** มีโค้ดสำหรับกระบวนการหลัก ได้แก่ บัญชีผู้ใช้ ห้องเรียน ข้อสอบ การส่งข้อความและรูปภาพ การตรวจด้วย AI การปรับคะแนนและอนุมัติ ประกาศ และรายงานคะแนน แต่ยังมีข้อกำหนดที่ขาด ฟังก์ชันที่เชื่อมต่อไม่สมบูรณ์ และยังไม่มีหลักฐานเพียงพอว่าผ่านการประเมินความแม่นยำตามบทที่ 3

ประเด็นที่ต้องจัดการก่อนสรุปว่าโครงงานครบ:

1. แก้ Auto-rubric: ตัวแปร Gemini client เป็น `None` ทำให้เส้นทางสร้างรูบริคตอบ 503
2. แก้การกู้คิวตรวจเมื่อเปิด backend: อ่าน `submissions.student_id` ทั้งที่ schema ใช้ `user_id`
3. บังคับสิทธิ์เข้าห้องและเวลาเริ่มสอบใน API ส่งคำตอบ และผูก `exam_id` กับห้องที่ผู้สอนมีสิทธิ์ใน API ตรวจ/อนุมัติ
4. ปิดคะแนนก่อนอนุมัติให้ครบทุก API รวมถึงประวัติการส่งงาน
5. เพิ่มออกจากห้อง จำกัด 300 คำ ถอดลายมือเป็นข้อความที่ตรวจสอบได้ และเตือนใกล้หมดเวลาพร้อมเวลาคงเหลือ
6. จัดชุดทดสอบจริง 300 คำตอบและผล QWK / MAE / Confusion Matrix ตามแผนในเอกสาร
7. ปรับรายละเอียดในเล่มให้ตรงกับโมเดล Prompt และขั้นตอนสมัครสมาชิกปัจจุบัน

ไม่ให้เปอร์เซ็นต์ความสำเร็จรวม เพราะการพบโค้ดไม่เท่ากับผลทดสอบผ่าน และข้อกำหนดมีความสำคัญไม่เท่ากัน

## 5. ช่องว่างที่ควรแก้ตามลำดับ

### G01 - Auto-rubric ใช้งานไม่ได้ตามเส้นทางปัจจุบัน (เร่งด่วน)

หลักฐาน: `server/services/ai_service.py:36` กำหนด `_genai_client = None`; `server/routes/ai_routes.py:25` คืน 503 หากไม่มี client การมี `_get_genai_client()` โดยไม่ได้เรียกไม่ทำให้พร้อมใช้งาน และ test ที่ mock client ไม่ตรวจเจอปัญหานี้

เกณฑ์ปิดงาน: เลือก provider ที่ใช้งานจริง ผูก client และทดสอบทั้งโจทย์ข้อความ/ภาพ ได้ answer_key/rubrics ที่รวมคะแนนถูกต้อง พร้อมกรณี API ไม่พร้อม

### G02 - startup recovery ใช้คอลัมน์ผิด (เร่งด่วน)

หลักฐาน: `server/main.py:93` ใช้ `SELECT id, exam_id, student_id FROM submissions WHERE status = 'submitted'`; DDL `database.py:155` มี `user_id` การรันกับ schema ตาม repo จะเกิด SQL error แม้ไม่มีแถวรอตรวจ เพราะชื่อคอลัมน์ไม่มี และอยู่ใน startup event โดยไม่มีตัวจับ exception รอบ query นี้

เกณฑ์ปิดงาน: เปิด backend ด้วย schema ตาม repo ได้ และเมื่อรีสตาร์ตขณะมี submitted ต้องนำงานกลับมาตรวจถูกผู้เรียนโดยไม่ทำซ้ำผิดรายการ

### G03 - การบังคับสิทธิ์และช่วงเวลายังไม่ครบ (เร่งด่วน)

- `exam_routes.py:209`: ตรวจว่าเป็น student และ exam อยู่ใน room แต่ไม่ได้ตรวจ enrollment ของผู้ส่ง และไม่ตรวจ `start_date`; ตรวจเฉพาะเวลาสิ้นสุดพร้อม grace period 1 นาที
- `exam_routes.py:160`: ตรวจสิทธิ์ห้องแล้วส่งโจทย์โดยไม่ตรวจเวลาเริ่ม; การปิดปุ่มใน ExamView ไม่ป้องกันการเรียก URL/API โดยตรง
- `exam_routes.py:465`, `:511`: ตรวจว่าครูเป็นเจ้าของ room ที่ส่งมา แต่ query submissions ใช้ exam_id โดยไม่ได้ยืนยันว่า exam นั้นอยู่ใน room ดังกล่าว

เกณฑ์ปิดงาน: นักเรียนนอกห้อง/ก่อนเริ่มสอบถูกปฏิเสธที่ server; ครูไม่สามารถอ่านหรืออนุมัติข้อสอบห้องอื่นด้วยการจับคู่ room_id ของตนกับ exam_id อื่น

หลักฐาน: `system_routes.py:70` เลือก total_score โดยไม่กรอง approved ขณะที่ worker `ai_service.py:135` บันทึกคะแนนตั้งแต่ ready/needs_review แม้ `StudentHistory.tsx:119` จะซ่อนการแสดงคะแนน

### G05 - ขอบเขตคำตอบและภาพยังไม่ครบ (สำคัญ)

เพิ่ม 300 คำทั้ง UI/API ตามนิยามคำไทย/อังกฤษที่ตกลงกัน; ส่งผล transcription กลับมาและเก็บหากต้องการทำตามข้อ 1.3.3.4 อย่างตรวจสอบได้; ทำจำนวนภาพที่ UI รับ backend เก็บ และ AI อ่านให้ตรงกัน ปัจจุบันรับ 10 แต่ตรวจ 5

เกณฑ์ปิดงาน: 300 คำผ่าน 301 คำถูกปฏิเสธอย่างชัดเจน; ภาพทุกภาพที่ระบบยอมรับถูกตรวจ หรือแจ้งจำกัดก่อนส่ง; ลายมือไทย/อังกฤษมีตัวอย่างและผลตรวจอ่านที่อ้างอิงได้

### G06 - ออกจากห้องและเวลา real-time (สำคัญ)

ยังไม่พบ leave endpoint/ปุ่มออกจากห้อง; deadline worker แจ้งครูเมื่อหมดเวลาแล้ว ไม่ใช่เตือนนักเรียนก่อนหมดเวลา; ExamSubmit ไม่มี countdown

เกณฑ์ปิดงาน: นักเรียนออกเฉพาะ enrollment ของตนได้โดยไม่ลบห้อง; เวลาคงเหลืออิงเวลาสอบจาก server และแจ้งก่อนหมดเวลาตามเกณฑ์ที่กำหนด

### G07 - ยังไม่มีผลทดลองตามข้อ 3.8 (สำคัญต่อการส่งโครงงาน)

- `Profile.tsx:32` ต่อ prefix ของ local upload เข้ากับ avatar URL ต้องรองรับ Cloudinary URL และทดสอบ refresh
- โฟลเดอร์ `docs_and_tests/` ถูก ignore ใน `.gitignore` รายงานจึงอยู่บนดิสก์ตามที่ร้องขอ แต่จะไม่ติด commit โดยอัตโนมัติ

## 6. ผลการตรวจที่ได้รันจริง

| การตรวจ | ผล | ข้อจำกัด |
| --- | --- | --- |
| อ่าน PDF และเทียบ SHA-256 สองตำแหน่ง | ผ่าน: 167 หน้าและไฟล์ตรงกัน | สกัดข้อความประกอบการดูภาพ DFD/ER |
| TypeScript: Node เรียก `node_modules/typescript/bin/tsc` | ผ่าน, exit code 0 | ตรวจชนิดข้อมูล frontend ไม่ยืนยัน backend/runtime |
| `pnpm typecheck` / `pnpm test` | เริ่มคำสั่งตาม script ไม่สำเร็จ | pnpm พยายามตรวจ/ติดตั้ง dependency และหยุดด้วย `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY`; ไม่ได้บังคับลบ/ติดตั้ง modules |
| Vitest ผ่าน Node เรียก `node_modules/vitest/vitest.mjs --run` | ยังรัน test ไม่ได้ | esbuild โหลด vite.config.ts ไม่สำเร็จ: `Cannot read directory "../..": Access is denied` เป็นปัญหาสภาพแวดล้อม ไม่ใช่ assertion ล้มเหลว |
| `.venv/Scripts/python.exe -m pytest tests/test_openai_grading.py tests/test_api.py -q` | ยังรัน test ไม่ได้ | interpreter ต้นทางของ virtual environment ไม่มีแล้ว |
| Python bundled รัน pytest เดิม | ยังรัน test ไม่ได้ | bundled runtime ไม่มี pytest |
| AI / TiDB / SMTP / Cloudinary / Firebase / Socket จริง | ไม่ได้รัน | จึงไม่มีข้อสรุปว่าบริการที่ deploy พร้อมใช้งาน |

ไฟล์ทดสอบที่พบ:

- `tests/test_api.py`: ping/docs/CORS/register/login/room/exam และ Auto-rubric แบบ mock ครอบคลุมเฉพาะบางเส้นทาง ไม่ได้พิสูจน์ provider จริงหรือการอนุมัติข้ามห้อง
- `tests/test_openai_grading.py`: ตรวจรูปแบบ request ภาพ/structured output และ fallback ไม่มี key ด้วย mock ไม่ได้วัดความแม่นยำ AI
- `client/lib/utils.spec.ts`: ทดสอบ utility ไม่ใช่ workflow ระบบตามเอกสาร
- `scripts/smoke_production_features.py`: มีสคริปต์ที่สร้าง/ลบข้อมูลในฐานข้อมูลที่ตั้งค่าไว้ ไม่ได้รันในงานตรวจรายงานนี้
