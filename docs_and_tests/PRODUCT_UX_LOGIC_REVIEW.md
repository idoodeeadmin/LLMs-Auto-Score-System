# Product, UX/UI และ logic review

วันที่ 16 กันยายน 2569

## ข้อสรุป

ระบบมีแนวทางหน้าตาที่ใช้งานต่อได้: โทนเขียวเข้ม พื้นหลังเรียบ และการแสดงงานเป็นรายการ ปัญหาหลักอยู่ที่หน้าต่าง ๆ ใช้รูปแบบและความหมายของสถานะไม่ตรงกัน รวมถึง UI บางจุดสื่อว่าทำงานได้ทั้งที่ logic ไม่รองรับ

รอบนี้เปิดเว็บในเบราว์เซอร์ ตรวจหน้าจอจริงทั้งโหมดสว่าง/มืดและจอมือถือ 390 px แล้วแก้จุดที่มีหลักฐาน ไม่ได้เปลี่ยนธีมหรือเพิ่มลูกเล่นใหม่ทั้งระบบ

## วิธีตรวจและขอบเขต

- เปิด frontend ที่ port 8080 เพื่อตรวจหน้าเข้าสู่ระบบ จากนั้นใช้ production build กับ fixture server ที่ `http://127.0.0.1:8090` สำหรับหน้าหลังเข้าสู่ระบบ
- ข้อมูลผู้สอน นักศึกษา คะแนน และ API ใน preview เป็นข้อมูลจำลองทั้งหมด ใช้แบบฟอร์มเข้าสู่ระบบปกติ ไม่มีการปิดระบบยืนยันตัวตนในแอปจริง
- หน้าที่เปิดตรวจ: เข้าสู่ระบบ, สมัครสมาชิก, ห้องเรียนของฉัน, ห้องเรียนรายวิชา, รายละเอียดข้อสอบ, สร้างข้อสอบ, แก้ไขข้อสอบ, รวมตรวจงาน, ตรวจรายคน, ประวัติของนักศึกษา, โปรไฟล์ และทำข้อสอบ
- ตรวจ source ประกอบสำหรับ route/API contract และการเปลี่ยนสถานะ; ไม่ได้ตรวจรับ Analytics, export, Firebase, SMTP, Socket หรือ OpenAI ด้วยบริการจริงในรอบนี้

## แนวทางการออกแบบที่ใช้

1. สีเขียวเข้มใช้กับการดำเนินการหลัก ส้มใช้กับงานที่ต้องตรวจทาน แดงใช้กับข้อผิดพลาด/การลบ ไม่ใช้สีตกแต่งแทนความหมาย
2. รายการตรวจเป็นงานต่อเนื่อง: เปิดรายการ → ตรวจคน → กลับรายการเดิม ไม่พาผู้สอนกลับจุดเริ่มทุกครั้ง
3. สถานะบนจอต้องตาม server; การกดสำเร็จไม่เท่ากับทุกรายการได้รับอนุมัติ
4. มือถือแยกแถวข้อมูลให้อ่านได้ ไม่บีบตาราง desktop; ปุ่มที่ใช้บ่อยต้องมองเห็นโดยไม่อาศัย hover
5. ลดกล่องยืนยันที่ไม่จำเป็นสำหรับการดาวน์โหลด Excel แต่คงการเตือนเรื่องข้อมูลที่ยังไม่บันทึก

## ผลตรวจ

- TypeScript: ผ่าน
- Vitest: 7 tests ผ่าน รวม regression tests เรื่องรายการกำลังตรวจและการอนุมัติบางรายการ
- Production build: ผ่าน; ยังมี warning เดิมเรื่อง Browserslist, PostCSS และขนาด bundle
- Browser: ตรวจการเลือกเฉพาะ ready, bulk approve ด้วย fixture, คง needs_review, แสดง queued/grading, layout จอเล็ก, สลับธีม, guard การแก้ไข และประวัติซ่อนคะแนนก่อนอนุมัติ
- ไม่เรียก AI จริง ไม่แก้คะแนนนักศึกษาจริง และไม่รัน benchmark

## สิ่งที่ยังต้องตรวจต่อก่อนเรียกว่า audit ครบทุกกรณี

- Modal เก่าบางหน้าสร้างด้วย div จึงยังควรย้ายไป Dialog ที่จัดการ focus/keyboard อย่างเป็นระบบ
- beforeunload และปุ่มกลับ/breadcrumb ของหน้าแก้ไขมี guard แล้ว แต่ยังไม่ได้ทำ SPA navigation blocker ครอบ browser Back และทุกหน้าแบบฟอร์ม
- หน้า Analytics และข้อมูล export ต้องตรวจหน่วย ตัวหาร สถานะที่รวมในการคำนวณ และ empty/error state กับชุดข้อมูลควบคุมแยกต่างหาก
- ยังมี utility classes เก่าหลายชุด จึงใช้ neutral color aliases เพื่อให้สม่ำเสมอในรอบนี้ ระยะถัดไปควรรวมเป็น components/tokens โดยตรง ไม่เพิ่ม CSS override ต่อไปเรื่อย ๆ
- ยังไม่ได้ทดสอบอุปกรณ์จริง, screen reader เต็ม workflow, network ช้า/ขาดหายทุกจังหวะ หรือหลายผู้ใช้พร้อมกัน

## เปิด preview ซ้ำ

```powershell
node node_modules/vite/bin/vite.js build --configLoader runner
node scripts/product-review-server.mjs
```

เปิด `http://127.0.0.1:8090` ใช้ `teacher@example.test` หรือ `student@example.test` และรหัสผ่านจำลองใดก็ได้ สคริปต์ bind เฉพาะ loopback และไม่เชื่อมต่อฐานข้อมูล/API จริง รองรับเฉพาะ endpoint สำหรับ review นี้ ไม่ใช้เป็น backend ของระบบจริง
