4.2 ระบบคิวประมวลผลการตรวจและคำนวณระดับความมั่นใจ (AI Grading Worker)

เนื่องจากการตรวจข้อสอบอัตนัยด้วยปัญญาประดิษฐ์ต้องใช้เวลาในการวิเคราะห์ข้อมูล (Inference Time) ผู้พัฒนาจึงได้ออกแบบระบบการทำงานแบบไม่ประสานเวลา (Asynchronous Background Worker) ด้วยระบบคิว เพื่อรองรับการส่งข้อสอบพร้อมกันของนักศึกษาจำนวนมากโดยไม่ทำให้เซิร์ฟเวอร์ติดขัด พร้อมระบบประเมินค่าความมั่นใจ (Confidence Evaluation) ดังนี้

  • Asynchronous Grading Queue: ใช้ asyncio.Queue ในการรับรายการข้อสอบที่นักศึกษากดส่ง และให้ Worker ดึงไปประมวลผลทีละรายการหลังฉาก
  • Confidence Metric Evaluation: ระบบจะตรวจสอบค่าความมั่นใจที่ AI ประเมินกลับมา หากข้อใดมีค่าความมั่นใจเป็น low (เช่น รูปภาพไม่ชัดเจน หรือคำตอบคลุมเครือมาก) ระบบจะเปลี่ยนสถานะใบส่งสอบนั้นเป็น needs_review อัตโนมัติ
  • Real-time WebSocket Notification: ทันทีที่ AI ตรวจข้อสอบเสร็จสิ้น ระบบจะส่งสัญญาณแจ้งเตือนผ่าน Socket.IO ไปยังหน้าจอของอาจารย์ผู้สอนแบบเรียลไทม์

4.3 ระบบอาจารย์ตรวจสอบและทบทวนผลการประเมิน (Teacher Review & Override System)

เพื่อรักษามนตรีและสิทธิขาดทางวิชาการ (Academic Integrity) ระบบได้ถูกออกแบบให้ปัญญาประดิษฐ์ทำหน้าที่เป็นเพียง "ผู้ช่วยประเมินเบื้องต้น" โดยอาจารย์ผู้สอนยังคงเป็นผู้มีอำนาจสูงสุดในการตัดสินใจ (Human-in-the-Loop) ผ่านฟีเจอร์การทบทวนและปรับแก้ผลคะแนนดังนี้

  • AI Feedback Review: อาจารย์สามารถคลิกดูรายละเอียดคำตอบของนักศึกษา พร้อมอ่านคำวิเคราะห์เหตุผลและจุดชี้แนะที่ AI ให้ไว้ในคอลัมน์ ai_feedback
  • Teacher Score Override: หากอาจารย์เห็นว่าการให้คะแนนของ AI คลาดเคลื่อน หรือต้องการให้คะแนนจิตพิสัยเพิ่มเติม สามารถกรอกคะแนนใหม่ลงในช่อง teacher_score ซึ่งระบบจะยึดคะแนนของอาจารย์เป็นหลักในการคำนวณเกรดทันที
  • Status Confirmation: เมื่ออาจารย์ตรวจทานเรียบร้อย สามารถกดปุ่มยืนยันเพื่อเปลี่ยนสถานะจาก needs_review ให้กลายเป็น ready ได้

ฟีเจอร์นี้ทำหน้าที่เป็นส่วนเตรียมข้อมูลเริ่มต้น (Data Preparation Flow) สำหรับอาจารย์ผู้สอน โดยเปิดให้สามารถสร้างห้องเรียน ออกรหัสเข้าร่วม (Class Code) และสร้างแบบทดสอบอัตนัย โดยมีจุดเด่นคือระบบรองรับการป้อนเกณฑ์การประเมินผล (Rubrics) แบบละเอียดรายข้อ เพื่อเป็นกรอบมาตรฐานให้ AI ทำการตรวจให้คะแนนได้อย่างสม่ำเสมอ

เมื่อกระบวนการตรวจข้อสอบเสร็จสิ้น ระบบจะประมวลผลข้อมูลคะแนนของนักศึกษาทั้งห้องเรียนออกมาเป็นรายงานทางสถิติและหน้าจอแดชบอร์ดสรุปผล เพื่อให้อาจารย์ผู้สอนสามารถประเมินผลสัมฤทธิ์ทางการเรียนรู้ของนักศึกษา วิเคราะห์ค่าเฉลี่ย ความแปรปรวน และนำผลคะแนนออกเป็นไฟล์เอกสารไปใช้ในการตัดเกรดได้อย่างสะดวกและแม่นยำ

4.6 การเชื่อมต่อและผลการทดลองประเมินคะแนนด้วยโมเดลภาษาขนาดใหญ่ (LLM Connection & Experimental Results)

ในส่วนของการประมวลผลตรวจข้อสอบอัตนัย ระบบได้ทำการเชื่อมต่อกับโมเดลภาษาขนาดใหญ่ (Large Language Model - LLM) โดยเลือกรูปแบบการเชื่อมต่อแบบ Public Cloud API Service ผ่านบริการ Google Gemini API (โมเดล gemini-flash-latest) ของ Google DeepMind แทนการติดตั้งแบบ Private Self-hosted บนเครื่องเซิร์ฟเวอร์ท้องถิ่น

4.6.1 เหตุผลและรูปแบบการเชื่อมต่อ (Public Cloud API)

  • เหตุผลที่ไม่ใช้ Private Self-hosted: การติดตั้งโมเดลขนาดใหญ่บนเครื่องเซิร์ฟเวอร์ท้องถิ่นต้องใช้การ์ดจอ (GPU) ราคาสูงและมีค่าใช้จ่ายดูแลรักษาสูง การเลือกใช้ Public Cloud API จึงช่วยประหยัดทรัพยากรและได้ความสามารถประมวลผลระดับ State-of-the-Art (SOTA)
  • Multimodal & OCR Capability: โมเดลรองรับข้อมูลประมวลผลแบบมัลติโมดัล สามารถอ่านข้อความ ถอดลายมือจากรูปภาพถ่ายกระดาษคำตอบ (OCR) และวิเคราะห์รูปภาพโจทย์ประกอบการให้คะแนนได้พร้อมกัน
  • Structured Output: กำหนดพารามิเตอร์ response_mime_type="application/json" และ temperature=0.2 เพื่อบังคับให้ LLM ตอบกลับเป็นโครงสร้าง JSON ที่คงเส้นคงวา

4.6.2 ขั้นตอนการขอรับกุญแจ API Key และการติดตั้งในโปรเจกต์อย่างปลอดภัย

การขอรับบริการจาก Google Gemini API ต้องดำเนินการผ่านระบบยืนยันตัวตนด้วยกุญแจลับ (API Key) โดยมีขั้นตอนเริ่มต้นตั้งแต่การสมัครขอรับกุญแจ จนถึงการนำมาตั้งค่าในโปรเจกต์อย่างปลอดภัยตามโค้ดจริงในระบบดังนี้:

ขั้นที่ 1: การขอรับกุญแจ API Key จาก Google AI Studio

ขั้นที่ 2: การนำกุญแจลับมาวางในไฟล์ .env (คีย์จริงในโปรเจกต์)

ขั้นที่ 3: การยกเว้นไฟล์ .env ด้วย .gitignore เพื่อป้องกันกุญแจหลุดขึ้น GitHub
